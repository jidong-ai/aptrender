## 가정

- 전시장에 헤드셋은 없다. 아이맥 화면이 "김민선 고객이 헤드셋으로 보는 시야(XR뷰)"를 대신한다.
- 관람객은 태블릿을 든 **매니저 역할**로, 정해진 순서를 안내(하이라이트·화살표)에 따라 진행한다.
- 테스트는 항상 맥북(서버 + XR Chrome), 전시는 아이맥 24". 렌더는 윈도우 PC(D5).
- 태블릿: iPad Air 4(A2316, 2360×1640 ≈ 10:7) 비율로 진행. 갤럭시 탭 S10 라이트로 바꿀 수 있음(아래).

## 1. 핵심 구조

```
[아이패드 Safari /tablet] ──WebSocket──▶ [Node 서버 :3000] ──WebSocket──▶ [Chrome /xr 전체화면]
                                          └ 단계(flow) 1개 보관 · 입력 검증 · 자동 진행 타이머 · 재접속 시 스냅샷
```

- **서버가 단계를 진행한다.** 태블릿은 "이 대상을 눌렀다"만 보내고, 서버가 `scenario.js` 규칙으로 검증해 다음 단계를 두 화면에 돌려준다. 늦게 도착한 중복 탭·잘못된 입력은 거부.
- **배경 고정 + 누끼 레이어(A안)** 유지. 겹치는 순서를 바닥재 → 아일랜드로 바꿔, 바닥재는 아일랜드 없이 렌더한다(조합 렌더 불필요).
- 주석은 방향(yaw·pitch) + 그린 공간으로 저장 → 태블릿 체크가 XR의 같은 자리에 그려진다.
- 없는 에셋은 와이어프레임으로 대신해 **처음부터 끝까지 항상 클릭 진행 가능**하게 둔다.

**게임형 규칙**: 가이드 대상만 누를 수 있다(다른 버튼은 막히고 대상이 흔들림). 파노라마 드래그는 항상 허용. UI 대상은 화면을 어둡게 하고 대상만 뚫어 펄스 링(#1AA0FF) + 지시문, 공간 대상(화살표·체크)은 펄스 링만, 시야 밖이면 가장자리 화살표.
**직원용**: 태블릿 왼쪽 위 2초 길게 누르기(리셋·단계 이동·HUD·격자), 아이맥 R·←/→, 90초 무입력 → 확인 10초 → 리셋.
