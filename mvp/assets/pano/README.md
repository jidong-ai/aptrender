# 파노라마 넣는 곳

D5에서 렌더한 360° equirectangular 이미지를 이 폴더에 넣는다. **JPG(압축본)와 누끼(`_cut.png`)만 GitHub에 올라가고**, 원본 PNG와 `built/`(pano:prep 결과)는 올라가지 않는다. 주고받는 방법은 [`../../README.md`](../../README.md) 2-1.

## 파일 이름 = 장면 ID

```
{ID}[_cut][_4k|_8k].jpg     예: kitchen_front.jpg, island_b_front.jpg, island_b_front_cut.png
```

크기 표시를 안 붙이면 8K로 본다. 대소문자·확장자(jpg/png/webp)는 상관없다. ID 목록은 `src/shared/scene.js`.

### 배경 (공간마다 1장)

| ID | 무엇 | 우선순위 |
|---|---|---|
| `kitchen_front` | 주방 정면 · 아일랜드 없음 · 기존 바닥 (기존 `pano_front`) | 있음 |
| `kitchen_side` | 주방 측면 · 아일랜드 없음 · 기존 바닥 (기존 `pano_side`) | 있음 |
| `store_1` | 위브 매장 입구 | 2 |
| `store_2` | 위브 매장 안쪽 | 3 (컷 라인: 없으면 매장 1장으로 줄임) |
| `counsel` | 상담실 | 2 |

### 레이어 (렌더 + 같은 이름의 `_cut.png` 누끼)

| ID | 겹치는 배경 | 렌더 조건 | 우선순위 |
|---|---|---|---|
| `island_b_front` | kitchen_front | 아일랜드 b(아떼 원목, 마호가니) · 900mm 지점 | **1** |
| `floor_portland_front` | kitchen_front | 바닥 포틀랜드 모티프 · **아일랜드 없이** | **1** |
| `island_a_front` | kitchen_front | 아일랜드 a(샤인 E0 렌지대 홈바) | 2 |
| `island_c_front` | kitchen_front | 아일랜드 c(도라 아일랜드 수납식탁) | 2 |
| `floor_flosso_front` | kitchen_front | 바닥 플로쏘 · 아일랜드 없이 | 2 |
| `island_b_side` | kitchen_side | 아일랜드 b 측면(안쪽 수납이 보이게) | 2 |
| `island_a_side` | kitchen_side | 기존 `island_a` 렌더(시나리오에는 안 씀, 보관) | – |

- 바닥재는 아일랜드 없이 렌더한다. 화면이 **바닥재 → 아일랜드** 순으로 겹치므로 아일랜드 3 × 바닥재 2 조합을 따로 렌더할 필요가 없다
- 누끼는 **6장**(우선순위 1·2의 레이어). 원본과 같은 크기, 배경 투명, 캔버스 자르지 않기
- `npm run pano:prep`이 아이패드용 4K JPG와 레이어를 `built/`에 만든다. 새 렌더를 받을 때마다 다시 실행
- 없는 것은 화면이 대신 그린다: 배경 → 테스트 격자(장면 이름 표시), 레이어 → 와이어프레임(이름표 상자·색 바닥)
- 누끼는 없고 아일랜드 렌더만 있으면 그 렌더를 통째로 보여준다(바닥재 변경 전까지)
- 인식된 파일 목록: `http://localhost:3000/api/panos`
- 웹 업로드는 한 장 25MB까지. 8K JPG 품질 80~90%면 대부분 넘지 않는다 ⚠️검증 필요
- 8K에서 GPU가 버티지 못하면 6K(6144×3072)로 렌더해도 동작한다(아이맥에서 약간 덜 선명) ⚠️검증 필요

## 바닥재 적용 영역 마스크 (Figma 펜툴)

누끼(`floor_*_cut.png`)가 오기 전, 바닥재를 칠할 **영역**을 Figma에서 직접 그려 지정할 수 있다. 없으면 `scene.js`의 `FLOOR_AREA` 기본 다각형을 쓴다.

1. Figma에서 **가로:세로 2:1 프레임**을 만든다(예: 2048×1024). 이름은 `kitchen_front_floor`
2. `kitchen_front.jpg`(=`pano_front.jpg`)를 프레임에 **꽉 차게**(0,0 기준, 프레임과 같은 크기) 깐다
3. 펜툴(P)로 바닥재를 깔 영역을 따라 그리고 채우기 색을 아무 색이나 넣는다. 곡선도 된다
4. 파노라마 이미지를 **숨기고**(눈 아이콘) 프레임을 선택 → Export → **SVG**(또는 PNG)
5. 파일 이름 `kitchen_front_floor.svg`로 GitHub `mvp/assets/pano/masks/`에 올린다 → 맥북 `git pull` → 새로고침

- 화면은 이 모양 안쪽만 와이어프레임 바닥재로 칠하고, 바닥재 '칠하기' 연출도 이 영역에서 일어난다
- 실제 바닥재 누끼(`floor_portland_front_cut.png` 등)가 들어오면 누끼가 우선이다. 누끼도 같은 방식(원본 크기 그대로, 영역 밖 투명)이라 이 마스크를 누끼 작업의 기준선으로 써도 된다

## 카메라·노출 체크 (중요)

- **같은 공간의 렌더는 카메라를 절대 움직이지 않는다.** 누끼는 배경 위 같은 자리에 겹쳐지므로, 조금만 움직여도 어긋난다
- **D5 노출·화이트밸런스를 수동으로 고정한다.** 자동 노출이면 오브제 톤이 배경과 달라져 떠 보인다 ⚠️검증 필요(D5 메뉴 위치는 버전마다 다름)
- 모든 공간의 카메라 **회전값(방향)을 똑같이** 둔다. 위치만 옮긴다. 그래야 "yaw 0° = 같은 벽"이 유지된다
- 매장·상담실 파노라마는 다음 공간 쪽(바닥 화살표를 둘 방향)이 화면 정면 근처에 오게 하면 체험이 자연스럽다
- 높이 1.6m(소비자 눈높이), 가로:세로 = 2:1
- 렌더가 오면 아일랜드 자리·900mm 지점·화살표 자리의 yaw·pitch를 재서 `scene.js`의 `ANCHORS`에 넣는다(README 5 "공간 좌표 재기")
