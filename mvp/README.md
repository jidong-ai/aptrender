# Weave MVP — 태블릿 ↔ XR뷰 연동

아이패드(매니저 태블릿)와 아이맥(소비자 XR 시야)이 같은 상담 장면을 실시간으로 공유한다.
인터넷 없이 같은 공유기 안에서만 동작한다.

```
[아이패드 Safari  /tablet] ──WebSocket──▶ [아이맥: Node 서버 :3000] ──WebSocket──▶ [아이맥 Chrome  /xr]
                                             └ 상태 1개 보관 · 접속/재접속 때 전체 스냅샷 전송
```

**현재 단계: v2 게임형 가이드 플로우 골격(M1).** 처음부터 끝까지 클릭으로 진행된다. 관람객이 눌러야 할 곳만 하이라이트되고, 나머지 버튼은 막힌다. 렌더·누끼·Figma 에셋이 없는 곳은 테스트 격자·와이어프레임으로 대신한다. 단계 정의는 [`docs/SCENARIO.md`](docs/SCENARIO.md), 일정은 [`docs/PLAN.md`](docs/PLAN.md).

**업데이트 받기** (맥북): 서버를 끄고(Ctrl+C) `mvp` 폴더에서

```bash
git pull
npm install      # 새 패키지(pretendard 폰트)가 추가됨
npm run ui:fetch # Figma 아이콘·이미지 받기(처음 한 번, 10/12 무렵 주소 만료)
npm run dev
```

---

## 1. 처음 한 번: 설치

1. Node.js 설치 — **22 LTS 권장** (최소 20.19 / 22.12). 터미널에서 `node -v`로 확인.
2. 터미널에서:

   ```bash
   cd aptrender/mvp
   npm install
   ```

인터넷은 이 설치 때만 필요하다. **전시장에 가기 전에 아이맥에서 미리 `npm install`까지 끝내 둔다.**

## 2. 실행

```bash
npm run dev
```

터미널에 이렇게 나온다(주소는 공유기마다 다름).

```
────────────────────────────────────────────────────────
  Weave MVP 서버  ·  개발 모드  ·  포트 3000
────────────────────────────────────────────────────────

  아이패드 (태블릿)     http://192.168.0.12:3000/tablet
  이 컴퓨터 (XR 화면)   http://localhost:3000/xr

  ▄▄▄▄▄▄▄ (QR 코드) ▄▄▄▄▄▄▄
  ↑ 아이패드 카메라로 QR을 비추면 태블릿 화면이 열립니다.
```

| 명령 | 언제 쓰나 |
|---|---|
| `npm run dev` | 개발 중. 코드를 고치면 화면이 자동 갱신된다 |
| `npm start` | 리허설·전시. 빌드한 뒤 실행해서 더 가볍고 안정적이다 |
| `npm test` | 단계 엔진·금액·서버 중계·재접속 자동 테스트 |
| `npm run ui:fetch` | Figma 아이콘·이미지를 `assets/ui/figma/`로 받는다. 없어도 와이어프레임 아이콘으로 동작 |
| `npm run pano:prep` | `assets/pano`의 렌더로 ① 아이패드용 4K JPG ② (원본이 PNG면) 아이맥용 8K JPG ③ 누끼 레이어를 `built/`에 만든다(이미 있으면 건너뜀) |
| `npm run pano:clean` | `built/`를 지운다(맥북 용량 정리, prep으로 다시 만들 수 있음) |

## 2-1. 렌더 이미지 넣기 (GitHub로 주고받기)

맥북 용량을 아끼려고 **압축본(JPG)과 누끼(`_cut.png`)만 GitHub에 올리고**, 맥북은 `git pull`로 받는다. 큰 원본 PNG는 맥북에 두지 않는다.

### 윈도우(렌더 PC)에서
1. D5 렌더를 **JPG로 저장**한다. D5 출력 형식을 JPG로 하거나, 포토샵에서 `파일 > 내보내기 > 다른 이름으로 내보내기 > JPG, 품질 80~90%`. **한 장 25MB 이하**여야 웹으로 올라간다 ⚠️검증 필요(이미지마다 다름)
2. 오브제·자재 장면은 **누끼 PNG**도 만든다(아래 "누끼 만드는 법")
3. GitHub 웹에서 `jidong-ai/aptrender` → 브랜치 `claude/gifted-gauss-n8os27` → `mvp/assets/pano` 폴더로 이동 → `Add file > Upload files`로 끌어다 놓고 `Commit changes`

### 맥북에서
```bash
cd ~/Desktop/aptrender-git/mvp   # 실제 위치로
git pull
npm run pano:prep
npm run dev
```
`pano:prep`이 아이패드용 4K와 레이어를 `assets/pano/built/`에 만든다(git에는 안 올라감). **새 렌더를 받을 때마다 다시 실행**한다.

### 맥북 용량 정리
- `assets/pano`의 **원본 PNG(누끼 `_cut.png` 제외)는 지워도 된다.** JPG를 GitHub에서 받으면 된다
- `npm run pano:clean` → `built/` 폴더를 지운다. 필요하면 `npm run pano:prep`으로 다시 만든다

파일 이름 = 장면 ID. 목록·규칙은 [`assets/pano/README.md`](assets/pano/README.md). 예전 D5 이름(`pano_front`, `pano_side`, `island_a`)도 그대로 인식한다.

### 배경 고정 + 레이어 방식 (A안)

XR 서비스의 "스캔한 공간은 그대로, 그 위에 오브제·자재를 올려 본다"를 보여주려고, 장면을 통째로 바꾸지 않는다.

- 공간마다 **배경** 한 장(`kitchen_front` 등)을 깔고, 아일랜드·바닥재는 **직접 딴 누끼**를 레이어로 겹친다
- 겹치는 순서는 **바닥재 → 아일랜드**. 그래서 바닥재 렌더는 **아일랜드 없이** 한다(아일랜드 3 × 바닥재 2 조합을 따로 렌더할 필요 없음)
- 연출
  - 아일랜드: 놓일 자리가 반투명하게 빛난 뒤 1.2° 위에서 내려앉음(약 1.1초)
  - 바닥재: 발밑에서 수평선 쪽으로 번져 나감(약 1.3초)
- XR이 다른 곳을 보고 있으면 먼저 고개를 돌리고, 그다음 연출이 시작된다
- 누끼가 없으면 **와이어프레임 레이어**(이름표 달린 상자·색 바닥)로, 배경 렌더가 없으면 **테스트 격자**로 대신한다. 흐름은 끊기지 않는다
- 누끼 없이 빠르게 미리 보고 싶으면 `npm run pano:prep -- --auto`(두 렌더 차이로 자동 오려내기. 경계가 부정확할 수 있음)

### 누끼 만드는 법 (포토샵 기준)
1. **옵션 렌더**(예: `island_b_front`)를 연다
2. 오브제만 남기고 나머지를 지운다(배경 투명). 바닥 그림자는 **부드러운 브러시로 반투명하게** 남기면 붙어 있는 느낌이 산다
3. **캔버스를 자르지 말고 원본과 같은 크기 그대로** PNG로 저장. 위치는 크기 그대로여야 맞는다
4. 이름은 원본 이름 + `_cut`: `island_b_front_cut.png`, `floor_flosso_front_cut.png`
5. 바닥재 누끼는 **바닥 영역만** 남긴다(아일랜드 없이 렌더했으므로 아일랜드 자리 바닥도 남긴다)
6. 25MB를 넘으면 4096×2048로 줄여 저장해도 동작한다(아이맥에서 약간 덜 선명)

**렌더 조건 (중요)**: 같은 시점의 렌더끼리 카메라가 움직이면 누끼가 배경과 어긋난다. **D5 노출·화이트밸런스도 수동으로 고정**해 오브제 색과 배경 톤이 맞게 한다. ⚠️검증 필요(D5 메뉴 위치는 버전마다 다름)

## 2-2. 윈도우 PC에서 실행하기

렌더 PC(윈도우)에서 바로 서버를 돌려도 된다. 아이패드와 같은 와이파이에 연결돼 있어야 한다.

1. [nodejs.org](https://nodejs.org)에서 **LTS** 설치, [git-scm.com](https://git-scm.com)에서 Git 설치
2. 시작 메뉴 → "PowerShell" 실행 후:

   ```powershell
   cd $HOME\Desktop
   git clone -b claude/gifted-gauss-n8os27 https://github.com/jidong-ai/aptrender.git aptrender-git
   cd aptrender-git\mvp
   npm install
   ```
3. `git pull` → `npm run pano:prep` → `npm run dev`
4. 처음 실행할 때 "Windows 보안 경고(방화벽)" 창이 뜨면 **개인 네트워크에 체크하고 액세스 허용** ⚠️검증 필요(윈도우 버전마다 문구가 다름)
5. XR 화면: 같은 PC의 Chrome에서 `http://localhost:3000/xr` (전체화면 F키)

## 3. XR 화면 열기 (맥북 / 아이맥)

1. Chrome에서 `http://localhost:3000/xr`
2. `F` 키로 전체화면

| 키 | 동작 |
|---|---|
| `F` | 전체화면 켜기/끄기 |
| `H` | 디버그 표시(왼쪽 위 상태창·점선) 숨기기/보이기 |
| `G` | 방위 격자 겹쳐 보기 (방향 검수용) |
| `S` | 미세한 흔들림 켜기/끄기 |
| `D` | 5초간 연결 끊기 (재접속 테스트) |
| `R` | 처음으로(리셋) |
| `←` `→` | 이전·다음 단계로 이동(직원용) |
| 마우스 드래그·휠 | 둘러보기·확대 (테스트용. 전시 때는 아무도 조작하지 않음) |

- 화면은 **1920×1080(16:9) 기준 무대**로 그린다. 맥북(16:10)에서는 위아래에 여백이 생기고, 점선 안쪽이 아이맥에서 보일 범위다.
- 전시 때 주소창 없이 띄우기: Chrome을 완전히 종료(⌘Q)한 뒤 터미널에서

  ```bash
  open -a "Google Chrome" --args --kiosk "http://localhost:3000/xr?hud=0"
  ```

  `?hud=0`은 디버그 표시를 숨긴 채로 시작한다. ⚠️검증 필요(Chrome 버전에 따라 kiosk 동작이 다를 수 있음)

## 4. 아이패드 접속 방법

**준비: 아이패드와 아이맥(맥북)이 같은 와이파이에 연결돼 있어야 한다.**

1. 아이맥에서 `npm run dev` 실행 → 터미널의 **"아이패드 (태블릿)"** 주소를 확인한다. XR 화면 왼쪽 위 상태창에도 같은 주소가 나온다.
2. 아이패드에서 둘 중 하나로 연다.
   - **QR**: 카메라 앱으로 터미널의 QR 코드를 비추고, 뜨는 링크를 탭
   - **직접 입력**: Safari 주소창에 `http://192.168.0.12:3000/tablet` 형식으로 입력. `http://`(https 아님)와 `:3000`까지 꼭 넣는다
3. 아이패드를 **가로**로 든다.
4. 시작화면의 **"상담 서비스 체험하기"**를 눌러 아이맥 화면이 함께 넘어가는지 본다.
5. 연결 상태를 보려면 왼쪽 위를 **2초 길게 눌러** 직원 메뉴 → "연결 정보(HUD)". 또는 주소 끝에 `?hud=1`

**iPadOS 16.4 이상**이 필요하다(설정 > 일반 > 정보에서 확인).

### 전시용 아이패드 세팅

- **주소창 숨기기**: Safari 공유 버튼 → "홈 화면에 추가" → 홈 화면 아이콘으로 실행 ⚠️검증 필요(iPadOS 버전마다 메뉴 위치가 다름)
- **자동 잠금 끄기**: 설정 > 디스플레이 및 밝기 > 자동 잠금 > 안 함
- **Safari 고정**: 설정 > 손쉬운 사용 > 사용법 유도(Guided Access) 켜고, 화면에서 측면 버튼 세 번

## 5. 체험 흐름 (게임형 가이드)

단계 전체 표: [`docs/SCENARIO.md`](docs/SCENARIO.md). 요약:

| 장 | 태블릿에서 누르는 곳 | XR(아이맥) |
|---|---|---|
| 0 오프닝 | 체험하기 → 캡션 '다음' → 바닥 화살표 2번(매장 → 상담실) | 대기 화면 |
| 1 로딩 | (자동 3.5초) "김민선 씨 XR 헤드셋을 착용중" | 부팅 화면 |
| 2 주방 | 둘러보기 → 치수확인 → 주석추가 → 점선 체크 따라 그리기 | 같은 주방 + 자막, 900mm 치수선, 같은 자리에 체크 + '매니저' |
| 3 아일랜드 | 오늘의집 → 오브제 → 가운데 제품 → '다음' → 상담상세 → 아일랜드 → 후보 3개 중 선택 | 배치 연출 → **XR만** 측면 → 정면 복귀 + 선택 제품 + 금액 |
| 4 바닥재 | 옵션수정 → 색상 칩 → 적용하기 → 상담상세 → 바닥 → 후보 2개 중 선택 | 발밑부터 바닥재 번짐 + 금액 |
| 5 아웃트로 | 상담 리포트 보내기 → (15초 뒤 자동으로 처음) | 리포트 도착 카드 |

- 캡션 화자: **안내**(태블릿에만) · **매니저** · **김민선 고객**(XR에도 자막)
- 눌러야 할 곳만 밝아지고 파란 링이 깜빡인다. 다른 버튼을 누르면 링이 흔들린다. 파노라마 드래그는 언제나 된다
- 주석 단계에서는 화면이 그리기 모드라 드래그로 둘러볼 수 없다. 점선을 60% 이상 따라 그리면 통과, 세 번 시도하면 그냥 넘어간다

### 직원용

- **직원 메뉴**: 태블릿 왼쪽 위 모서리를 **2초 길게 누르기** → 처음으로 / 이전·다음 단계 / 단계 목록에서 이동 / 연결 정보 / 방위 격자 / 5초 끊기 / 화면 중앙 좌표
- **자동 리셋**: 체험 중 90초 동안 아무 입력이 없으면 "계속하시겠어요?" → 10초 뒤 처음으로
- 아이맥 키보드: `R` 처음으로, `←` `→` 단계 이동
- **공간 좌표 재기**(렌더가 오면): 직원 메뉴 → 연결 정보(HUD)를 켜고, 재고 싶은 곳(아일랜드 자리, 900mm 지점, 매장 바닥 화살표 자리)을 화면 가운데에 둔 뒤 HUD의 yaw·pitch를 `src/shared/scene.js`의 `ANCHORS`에 넣는다

### M1 클릭 테스트 체크리스트 (맥북 + 아이패드)

- [ ] 시작화면 → 엔딩까지 하이라이트만 따라 눌러서 끝까지 간다. 엔딩 15초 뒤 시작화면으로 돌아간다
- [ ] 하이라이트가 아닌 버튼(예: 고객정보)을 누르면 넘어가지 않고 링이 흔들린다
- [ ] 바닥 화살표를 누르면 그쪽으로 다가가며(돌리) 다음 공간으로 넘어간다
- [ ] 로딩 3.5초 뒤 두 화면이 함께 주방으로 들어가고 타이머가 0부터 흐른다
- [ ] 치수확인 → 두 화면에 같은 위치의 900mm 치수선
- [ ] 점선 체크를 따라 그리면 XR 같은 자리에 체크가 그려지는 과정이 보이고 '매니저' 라벨이 붙는다
- [ ] 가운데 제품(아떼) → XR이 아일랜드 쪽으로 고개를 돌린 뒤 아일랜드가 내려앉음 + 알림 → 고객 대사 2.5초 뒤 XR만 측면
- [ ] 후보 a/b/c를 바꿔 고르면 XR 아일랜드·금액이 그 제품으로 바뀐다
- [ ] 적용하기 → 바닥재가 발밑부터 번진다. 후보 2개 중 고른 바닥재로 XR이 바뀐다
- [ ] 진행 중 XR 탭 새로고침 → 같은 단계·선택으로 복구
- [ ] 직원 메뉴로 아무 단계나 이동, 처음으로 리셋
- [ ] 90초 손 놓기 → 확인 창 → 10초 뒤 처음으로
- [ ] 흐름·문구·순서에서 어색한 곳을 메모해 피드백

## 5-2. Day 1 확인 체크리스트 (연동·재접속)

- [ ] 아이패드에서 가이드 대상을 누르면 아이맥 화면이 **1초 안에** 바뀐다. 태블릿 상태창의 `RTT`가 아이패드↔서버 왕복 시간이다. 같은 공유기라면 대개 100ms 미만 ⚠️검증 필요(공유기·전파 환경에 따라 다름)
- [ ] 태블릿 상태창에 `접속 중: 태블릿 1 · XR 1`

**재접속 테스트** — 끊겼다 다시 붙을 때 현재 상태를 다시 받아오는지 확인한다.

- [ ] **A. XR만 끊기**: XR 화면에서 `D` → 5초 끊긴 동안 아이패드에서 다음 단계로 → 5초 뒤 XR이 **그 단계**로 바뀐다. XR 상태창 기록에 `스냅샷 2번째 수신 · 상태 복구`
- [ ] **B. 태블릿만 끊기**: 직원 메뉴 "5초 끊기" → 5초 뒤 복귀
- [ ] **C. 아이패드 잠금**: 잠금 → 10초 뒤 해제 → 자동으로 "● 연결됨"
- [ ] **D. XR 탭 닫기**: XR 탭을 닫고 → 아이패드에서 진행 → XR을 다시 열면 그 단계로 시작
- [ ] **E. 서버 재시작**: 터미널에서 Ctrl+C → 두 화면 "× 끊김" → 다시 `npm run dev` → 자동 재연결. 단, 상태는 처음(시작화면)으로 돌아간다(서버 메모리에만 저장)

터미널에도 접속·끊김·변경이 시간순으로 찍힌다.

```
[14:02:11] + tablet#1 접속 (192.168.0.23) · 태블릿 1 · XR 1
[14:02:15] tablet#1 → start · S0-0 → S0-1 (rev 1)
[14:02:20] - xr#2 연결 끊김 (재접속 테스트) · 태블릿 1 · XR 0
```

## 6. 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 아이패드에서 페이지가 안 열림 (계속 로딩) | ① 두 기기 와이파이 이름이 같은지 ② 주소에 `http://`와 `:3000`이 있는지 ③ 맥 방화벽: 처음 실행 때 "node가 들어오는 연결을 허용할까요?" 팝업이 뜨면 **허용**. 놓쳤다면 시스템 설정 > 네트워크 > 방화벽 > 옵션에서 node 허용 ⚠️검증 필요 ④ 터미널의 "다른 주소 후보"로 시도 |
| 집에선 되는데 학교·전시장 와이파이에서만 안 됨 | 공용 와이파이는 기기끼리 통신을 막아 둔 경우가 많다(AP isolation). **인터넷 없는 트래블 라우터**를 따로 켜고 두 기기만 연결한다. 서버가 아이맥 안에 있어서 인터넷은 필요 없다 |
| 어제 되던 주소가 오늘 안 됨 | 공유기가 IP를 새로 줬다. 터미널 주소를 다시 확인. 트래블 라우터 설정에서 아이맥 IP를 고정(DHCP 예약)해 두면 매번 같다 |
| `3000 포트를 이미 다른 프로그램이 쓰고 있습니다` | 이전에 켠 서버 터미널 창을 닫는다. 또는 `PORT=3001 npm run dev` |
| 터미널 주소가 이상함 (10.x, 100.x 등) | VPN을 끈다 |
| `LAN 주소를 찾지 못했습니다` | 맥의 와이파이 연결 확인 |
| 태블릿 상태창이 `XR 0` | 아이맥 Chrome에 `/xr` 탭이 열려 있는지 확인 |
| 파노라마 대신 격자만 보임 | ① 파일이 `mvp/assets/pano/`에 있는지 ② 이름이 규칙에 맞는지(`assets/pano/README.md`) ③ 상태창 기록에 "불러오기 실패"가 있는지 |
| 아이패드 사파리가 파노라마를 띄우다 새로고침됨 | 메모리 부족. 4K(4096×2048) 파일을 쓰는지 확인. 8K만 있으면 태블릿이 줄여서 쓰지만 디코딩 때 메모리를 많이 쓴다 ⚠️검증 필요 |
| macOS 15 이상에서 연결이 막힘 | 시스템 설정 > 개인정보 보호 및 보안 > 로컬 네트워크에서 터미널 허용 ⚠️검증 필요 |

**IP 대신 이름으로 접속**: 맥 이름 기반 주소(예: `http://weave-imac.local:3000/tablet`)도 쓸 수 있다. IP가 바뀌어도 그대로다. 이름은 시스템 설정 > 일반 > 공유 > 로컬 호스트 이름에서 확인. ⚠️검증 필요(공유기에 따라 안 될 수 있음)

## 8. 상태와 메시지 (개발 참고)

서버가 단일 진실이다. 두 화면은 서버가 확정해 돌려준 단계로만 그린다. 태블릿에서 눌러도 서버가 검증해 돌려주기 전에는 화면이 바뀌지 않는다.

```js
{
  flow: {
    step: "S0-0",                // scenario.js의 단계 ID
    enteredAt: number,           // 단계에 들어온 서버 시각
    timerAt: number | null,      // 상담 타이머 시작(S2-1)
    choices: { island: null | "a"|"b"|"c", floor: null | "portland"|"flosso" }
  },
  strokes: [{ id, tool: "pencil"|"highlighter"|"pen", width, color, pano, pts: [[yaw, pitch], ...] }],   // pano = 그린 공간
  managerView: { yaw, pitch, fov, aspect }   // 태블릿 시점. 10Hz
}
```

| 방향 | type | 내용 |
|---|---|---|
| 태블릿 → 서버 | `flow` | `{ from, action, value }` 가이드 대상을 눌렀음. 서버가 `nextStep`으로 검증(지난 단계·대상 아님·허용 안 된 값은 거부) |
| | `jump` | `{ step }` 직원용 단계 이동. 건너뛴 선택은 기본값(아떼·포틀랜드 모티프)으로 채움 |
| | `patch` | `{ patch: { managerView } }` 시점 공유만 |
| | `stroke:start` · `append` · `end` · `erase` | 주석. append는 50ms 배치, 1회 최대 200점 |
| | `reset` · `ping` | 처음으로 · 연결 확인 |
| 서버 → 화면 | `hello` | 접속 직후. 클라이언트 번호, 서버 시각, 아이패드 접속 주소 |
| | `snapshot` | 전체 상태. 접속·재접속·리셋·jump 때 |
| | `flow` · `patch` · `stroke:*` | 변경 중계 (`rev`, `from` 포함) |
| | `peers` · `error` | 접속 수 · 거부 사유 |

- 자동 진행(로딩 3.5초, 엔딩 15초 → 리셋)은 **서버가** 잰다. 화면이 잠깐 끊겨도 같은 시점에 넘어간다
- `GET /api/panos` → `{ panos, layers }`, `GET /api/ui` → `{ files }`(받아 둔 Figma 에셋)
- 상태는 서버 메모리에만 있다. 서버를 다시 켜면 시작화면으로 돌아간다
