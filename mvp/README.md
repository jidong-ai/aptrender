# Weave MVP — 태블릿 ↔ XR뷰 연동

아이패드(매니저 태블릿)와 아이맥(소비자 XR 시야)이 같은 상담 장면을 실시간으로 공유한다.
인터넷 없이 같은 공유기 안에서만 동작한다.

```
[아이패드 Safari  /tablet] ──WebSocket──▶ [아이맥: Node 서버 :3000] ──WebSocket──▶ [아이맥 Chrome  /xr]
                                             └ 상태 1개 보관 · 접속/재접속 때 전체 스냅샷 전송
```

**현재 단계: Day 2 파노라마 뷰어.** 두 화면이 같은 360° 파노라마를 각자 다른 방향으로 보고, XR 화면에 "매니저가 보는 곳" 테두리가 뜬다. 버튼은 아직 회색 임시 UI다.

**업데이트 받기** (맥북에서 git으로 받았다면): 서버를 끄고(Ctrl+C) `mvp` 폴더에서

```bash
git pull
npm install   # 새 패키지(three.js)가 추가됐을 때 필요
npm run dev
```

---

## 1. 처음 한 번: 설치

1. Node.js 설치 — **22 LTS 권장** (최소 20.19 / 22.12). 터미널에서 `node -v`로 확인.
2. 터미널에서:

   ```bash
   cd aptrender/mvp
   npm install
   ```

인터넷은 이 설치 때만 필요하다. **전시장에 가기 전에 아이맥에서 미리 `npm install`까지 끝내 둔다.**

## 2. 실행

```bash
npm run dev
```

터미널에 이렇게 나온다(주소는 공유기마다 다름).

```
────────────────────────────────────────────────────────
  Weave MVP 서버  ·  개발 모드  ·  포트 3000
────────────────────────────────────────────────────────

  아이패드 (태블릿)     http://192.168.0.12:3000/tablet
  이 컴퓨터 (XR 화면)   http://localhost:3000/xr

  ▄▄▄▄▄▄▄ (QR 코드) ▄▄▄▄▄▄▄
  ↑ 아이패드 카메라로 QR을 비추면 태블릿 화면이 열립니다.
```

| 명령 | 언제 쓰나 |
|---|---|
| `npm run dev` | 개발 중. 코드를 고치면 화면이 자동 갱신된다 |
| `npm start` | 리허설·전시. 빌드한 뒤 실행해서 더 가볍고 안정적이다 |
| `npm test` | 서버 중계·재접속 자동 테스트 |
| `npm run pano:prep` | `assets/pano`의 8K 렌더로 아이패드용 4K JPG와 아이맥용 8K JPG를 만든다(윈도우·맥, 이미 있으면 건너뜀) |

## 2-1. 렌더 이미지 넣기 (git에 올리지 않음)

파노라마는 용량이 커서 GitHub에 올리지 않는다(웹 업로드는 파일당 25MB 제한). **서버를 돌릴 컴퓨터의 `mvp/assets/pano` 폴더에 직접 복사**한다. 윈도우에서 맥으로 옮길 때는 USB나 구글 드라이브를 쓴다.

1. D5에서 뽑은 파일을 `mvp/assets/pano`에 복사(이름 규칙: `assets/pano/README.md`)
2. 터미널에서 `npm run pano:prep` → 아이패드용 4K, 아이맥용 8K JPG가 자동으로 생긴다
3. `npm run dev`. 이미 켜 둔 상태면 두 화면만 새로고침

지금 연결된 D5 파일 이름(그대로 넣으면 됨):

| 파일 | 장면 |
|---|---|
| `pano_front.png` | 정면 · 아일랜드 없음 · 기존 바닥 |
| `pano_side.png` | 측면 · 아일랜드 없음 · 기존 바닥 |
| `island_a.png` | 정면 · 아일랜드 2 배치 · 기존 바닥 |

확장자는 jpg·png 상관없다. 새 이름을 쓰고 싶으면 `src/shared/scene.js`의 `ALIASES`에 한 줄 추가한다.

## 2-2. 윈도우 PC에서 실행하기

렌더 PC(윈도우)에서 바로 서버를 돌려도 된다. 아이패드와 같은 와이파이에 연결돼 있어야 한다.

1. [nodejs.org](https://nodejs.org)에서 **LTS** 설치, [git-scm.com](https://git-scm.com)에서 Git 설치
2. 시작 메뉴 → "PowerShell" 실행 후:

   ```powershell
   cd $HOME\Desktop
   git clone -b claude/gifted-gauss-n8os27 https://github.com/jidong-ai/aptrender.git aptrender-git
   cd aptrender-git\mvp
   npm install
   ```
3. 렌더 파일을 `aptrender-git\mvp\assets\pano`에 복사 → `npm run pano:prep` → `npm run dev`
4. 처음 실행할 때 "Windows 보안 경고(방화벽)" 창이 뜨면 **개인 네트워크에 체크하고 액세스 허용** ⚠️검증 필요(윈도우 버전마다 문구가 다름)
5. XR 화면: 같은 PC의 Chrome에서 `http://localhost:3000/xr` (전체화면 F키)

## 3. XR 화면 열기 (맥북 / 아이맥)

1. Chrome에서 `http://localhost:3000/xr`
2. `F` 키로 전체화면

| 키 | 동작 |
|---|---|
| `F` | 전체화면 켜기/끄기 |
| `H` | 디버그 표시(왼쪽 위 상태창·점선) 숨기기/보이기 |
| `G` | 방위 격자 겹쳐 보기 (방향 검수용) |
| `S` | 미세한 흔들림 켜기/끄기 |
| `D` | 5초간 연결 끊기 (재접속 테스트) |
| 마우스 드래그·휠 | 둘러보기·확대 (테스트용. 전시 때는 아무도 조작하지 않음) |

- 화면은 **1920×1080(16:9) 기준 무대**로 그린다. 맥북(16:10)에서는 위아래에 여백이 생기고, 점선 안쪽이 아이맥에서 보일 범위다.
- 전시 때 주소창 없이 띄우기: Chrome을 완전히 종료(⌘Q)한 뒤 터미널에서

  ```bash
  open -a "Google Chrome" --args --kiosk "http://localhost:3000/xr?hud=0"
  ```

  `?hud=0`은 디버그 표시를 숨긴 채로 시작한다. ⚠️검증 필요(Chrome 버전에 따라 kiosk 동작이 다를 수 있음)

## 4. 아이패드 접속 방법

**준비: 아이패드와 아이맥(맥북)이 같은 와이파이에 연결돼 있어야 한다.**

1. 아이맥에서 `npm run dev` 실행 → 터미널의 **"아이패드 (태블릿)"** 주소를 확인한다. XR 화면 왼쪽 위 상태창에도 같은 주소가 나온다.
2. 아이패드에서 둘 중 하나로 연다.
   - **QR**: 카메라 앱으로 터미널의 QR 코드를 비추고, 뜨는 링크를 탭
   - **직접 입력**: Safari 주소창에 `http://192.168.0.12:3000/tablet` 형식으로 입력. `http://`(https 아님)와 `:3000`까지 꼭 넣는다
3. 아이패드를 **가로**로 든다.
4. 왼쪽 위 상태창이 **"● 연결됨"**, **"접속 중: 태블릿 1 · XR 1"** 이면 연동 완료.
5. A / B / C를 눌러 아이맥 색이 바뀌는지 본다.

**iPadOS 16.4 이상**이 필요하다(설정 > 일반 > 정보에서 확인).

### 전시용 아이패드 세팅

- **주소창 숨기기**: Safari 공유 버튼 → "홈 화면에 추가" → 홈 화면 아이콘으로 실행 ⚠️검증 필요(iPadOS 버전마다 메뉴 위치가 다름)
- **자동 잠금 끄기**: 설정 > 디스플레이 및 밝기 > 자동 잠금 > 안 함
- **Safari 고정**: 설정 > 손쉬운 사용 > 사용법 유도(Guided Access) 켜고, 화면에서 측면 버튼 세 번

## 5. 60초 체험 스크립트 (확정본)

| 초 | 관람객(태블릿) | XR 화면에 보이는 것 | 바뀌는 상태 |
|---|---|---|---|
| 0–10 | 둘러보기(드래그·핀치), 정면 ↔ 측면 시점 이동 | 매니저 시선 테두리가 따라 움직임. 시점을 옮기면 함께 이동 | `managerView`, `spot` |
| 10–25 | 아일랜드 1·2·3 중 **2** 배치 | 크로스페이드 + "아일랜드 2 배치 · 매니저가 변경" + 아일랜드 쪽으로 시선 이동 | `island` |
| 25–35 | 바닥재 A·B·C 중 **B** 선택 | 크로스페이드 + "바닥재 B로 변경" + 바닥 쪽으로 시선 이동 | `floor` |
| 35–50 | 주석: 아일랜드 위 체크 표시 | 그려지는 과정 그대로 + '매니저' 라벨 (D5) | `strokes` |
| 50–60 | 하단 메뉴 '적용제품' | 우측 패널 목록·금액 갱신 (D6) | `panel` |

- 조도 조절은 이 흐름에서 뺐다.
- 바닥재는 아일랜드를 놓은 뒤에만 고를 수 있다. "없음"을 누르면 바닥도 기존으로 돌아간다. 렌더 장수를 줄이기 위한 규칙이다.
- 시점은 매니저·고객이 **함께 이동**한다(안 1). 상태에는 `spot.manager`·`spot.customer`가 나뉘어 있어서, 나중에 "다른 자리에서 같은 대상 보기"(안 2)로 넓힐 수 있다.

## 5-00. 25초 플로우 테스트 (지금 있는 렌더 3장)

| 초 | 태블릿 | XR에서 확인할 것 |
|---|---|---|
| 0–10 | 드래그로 둘러보기 → **측면** → 다시 **정면** | 두 화면이 함께 시점을 옮기고 "측면으로 이동" 알림. 매니저 시선 테두리가 따라옴 |
| 10–25 | 아일랜드 **2** | 0.8초 크로스페이드로 `island_a`가 나타나고 "아일랜드 2 배치" 알림, 아일랜드 쪽으로 시선 이동 |

- 측면에서 아일랜드를 놓으면 측면 렌더가 아직 없어서 테스트 격자가 보인다(버튼 점선 = 렌더 없음). 시나리오대로 **정면에서** 놓으면 된다.
- 아일랜드 1·3, 바닥재 A·B·C도 아직 렌더가 없어 격자로 보인다.
- XR이 돌아보는 방향이 실제 아일랜드와 어긋나면: 태블릿에서 아일랜드를 화면 가운데 두고 오른쪽 위 yaw·pitch를 읽어 `src/shared/scene.js`의 `targets.island`에 넣는다.

## 5-0. 장면 전환 확인 체크리스트

- [ ] 아일랜드 "없음"일 때 바닥재 A·B·C가 흐리게 잠겨 있다
- [ ] 아일랜드 2 → XR 위쪽에 "아일랜드 2 배치 · 매니저가 변경"이 3초 뜨고, XR이 다른 곳을 보고 있었다면 아일랜드 쪽으로 천천히 돌아간다
- [ ] 바닥재 B → "바닥재 B로 변경" + XR이 바닥 쪽으로 내려다본다
- [ ] 시점 V2 → 두 화면이 함께 V2로 바뀌고 "아일랜드 앞으로 이동"
- [ ] 렌더가 없는 조합은 테스트 격자에 장면 이름이 적혀 보인다(버튼 테두리 점선 = 렌더 없음)
- [ ] XR이 돌아가는 목표 방향이 실제 아일랜드·바닥 위치와 어긋나면 `src/shared/scene.js`의 `targets` 숫자를 고친다. 태블릿 오른쪽 위 yaw·pitch로 실제 위치를 재서 넣으면 된다

## 5-1. Day 2 확인 체크리스트 (파노라마 뷰어)

**완료 기준: 두 기기가 같은 장면을 다른 방향으로 본다.**

태블릿 조작: **1손가락 드래그 = 둘러보기, 두 손가락 벌리기/모으기 = 확대/축소**. 오른쪽 위에 현재 yaw·pitch·fov가 나온다.

- [ ] 두 화면 모두 화이트 매스 파노라마가 뜬다. 상태창 기록에 `파노라마 v1_none_base 준비 (…초)`
- [ ] 아이패드를 돌려도 아이맥 화면은 그대로다(독립 시점). 아이맥 화면은 아주 약하게 흔들린다(`S`로 끄기)
- [ ] 아이패드가 보는 영역이 아이맥 화면에 흰 테두리 + "매니저가 보는 곳"으로 뜨고, 아이패드를 돌리면 따라 움직인다
- [ ] 아이패드에서 확대하면 아이맥의 테두리가 작아진다
- [ ] 아이패드를 뒤쪽으로 돌리면 아이맥 화면 가장자리에 "매니저 시선" 화살표가 뜬다
- [ ] 옵션을 바꾸면 0.8초 동안 겹쳐지며 바뀐다
- [ ] 아이패드 새로고침 → 보던 방향 그대로 다시 열린다
- [ ] 아이패드 "방위 격자"(아이맥은 `G`) → 두 화면에서 같은 벽이 같은 각도 숫자에 걸린다. D5 주석 정렬의 기준이 된다
- [ ] 4K 파노라마를 띄운 채 1~2분 둘러봐도 사파리가 새로고침되거나 꺼지지 않는다 ⚠️검증 필요(기기별 메모리 한계)

**방향 규칙**: 파노라마 이미지 가로 중앙 = yaw 0°(정면). 오른쪽으로 돌수록 +, 위를 볼수록 pitch +. 지금 화이트 매스 이미지는 정면에 주방·아일랜드가 있다.

## 5-2. Day 1 확인 체크리스트 (연동·재접속)

- [ ] 아이패드 버튼 → 아이맥 화면이 **1초 안에** 바뀐다. 태블릿 상태창의 `RTT`가 아이패드↔서버 왕복 시간이다. 같은 공유기라면 대개 100ms 미만 ⚠️검증 필요(공유기·전파 환경에 따라 다름)
- [ ] 태블릿 상태창에 `접속 중: 태블릿 1 · XR 1`

**재접속 테스트** — 끊겼다 다시 붙을 때 현재 상태를 다시 받아오는지 확인한다.

- [ ] **A. XR만 끊기**: XR 화면에서 `D` → 5초 끊긴 동안 아이패드에서 다른 버튼 → 5초 뒤 XR이 **새 장면**으로 바뀐다. XR 상태창 기록에 `스냅샷 2번째 수신 · 상태 복구`
- [ ] **B. 태블릿만 끊기**: 아이패드 "5초간 연결 끊기" → 버튼이 흐려짐 → 5초 뒤 복귀
- [ ] **C. 아이패드 잠금**: 잠금 → 10초 뒤 해제 → 자동으로 "● 연결됨"
- [ ] **D. XR 탭 닫기**: XR 탭을 닫고 → 아이패드에서 버튼 변경 → XR을 다시 열면 바뀐 색으로 시작
- [ ] **E. 서버 재시작**: 터미널에서 Ctrl+C → 두 화면 "× 끊김" → 다시 `npm run dev` → 자동 재연결. 단, 상태는 처음(V1 · 아일랜드 없음 · 기존 바닥)으로 돌아간다(서버 메모리에만 저장)

터미널에도 접속·끊김·변경이 시간순으로 찍힌다.

```
[14:02:11] + tablet#1 접속 (192.168.0.23) · 태블릿 1 · XR 1
[14:02:15] tablet#1 → island="2" (rev 1)
[14:02:20] - xr#2 연결 끊김 (재접속 테스트) · 태블릿 1 · XR 0
```

|---|---|
| 아이패드에서 페이지가 안 열림 (계속 로딩) | ① 두 기기 와이파이 이름이 같은지 ② 주소에 `http://`와 `:3000`이 있는지 ③ 맥 방화벽: 처음 실행 때 "node가 들어오는 연결을 허용할까요?" 팝업이 뜨면 **허용**. 놓쳤다면 시스템 설정 > 네트워크 > 방화벽 > 옵션에서 node 허용 ⚠️검증 필요 ④ 터미널의 "다른 주소 후보"로 시도 |
| 집에선 되는데 학교·전시장 와이파이에서만 안 됨 | 공용 와이파이는 기기끼리 통신을 막아 둔 경우가 많다(AP isolation). **인터넷 없는 트래블 라우터**를 따로 켜고 두 기기만 연결한다. 서버가 아이맥 안에 있어서 인터넷은 필요 없다 |
| 어제 되던 주소가 오늘 안 됨 | 공유기가 IP를 새로 줬다. 터미널 주소를 다시 확인. 트래블 라우터 설정에서 아이맥 IP를 고정(DHCP 예약)해 두면 매번 같다 |
| `3000 포트를 이미 다른 프로그램이 쓰고 있습니다` | 이전에 켠 서버 터미널 창을 닫는다. 또는 `PORT=3001 npm run dev` |
| 터미널 주소가 이상함 (10.x, 100.x 등) | VPN을 끈다 |
| `LAN 주소를 찾지 못했습니다` | 맥의 와이파이 연결 확인 |
| 태블릿 상태창이 `XR 0` | 아이맥 Chrome에 `/xr` 탭이 열려 있는지 확인 |
| 파노라마 대신 격자만 보임 | ① 파일이 `mvp/assets/pano/`에 있는지 ② 이름이 규칙에 맞는지(`assets/pano/README.md`) ③ 상태창 기록에 "불러오기 실패"가 있는지 |
| 아이패드 사파리가 파노라마를 띄우다 새로고침됨 | 메모리 부족. 4K(4096×2048) 파일을 쓰는지 확인. 8K만 있으면 태블릿이 줄여서 쓰지만 디코딩 때 메모리를 많이 쓴다 ⚠️검증 필요 |
| macOS 15 이상에서 연결이 막힘 | 시스템 설정 > 개인정보 보호 및 보안 > 로컬 네트워크에서 터미널 허용 ⚠️검증 필요 |

**IP 대신 이름으로 접속**: 맥 이름 기반 주소(예: `http://weave-imac.local:3000/tablet`)도 쓸 수 있다. IP가 바뀌어도 그대로다. 이름은 시스템 설정 > 일반 > 공유 > 로컬 호스트 이름에서 확인. ⚠️검증 필요(공유기에 따라 안 될 수 있음)

## 8. 상태와 메시지 (개발 참고)

서버가 단일 진실이다. 두 화면은 서버가 확정해 돌려준 값으로만 그린다(태블릿 버튼의 선택 표시도 마찬가지).

```js
{
  spot: { manager: "v1"|"v2", customer: "v1"|"v2" },   // v1 정면, v2 측면. 지금은 함께 이동
  island: "none" | "1" | "2" | "3",
  floor: "base" | "a" | "b" | "c",   // base = 기존 바닥
  dims: boolean,
  strokes: [{ id, tool: "pencil"|"highlighter"|"pen", width, color, spot, pts: [[yaw, pitch], ...] }],   // spot = 그린 시점
  managerView: { yaw, pitch, fov, aspect },   // 태블릿 시점. fov = 세로 시야각, aspect = 화면비. 10Hz
  panel: null | "client" | "detail" | "products" | "ohouse",
  call: { active: boolean },
  recStartedAt: number
}
```

- 각도 단위는 도(°). yaw −180~180, pitch −90~90(위가 +), fov 10~120
- 파노라마 목록: `GET /api/panos` → `assets/pano`에 실제로 있는 파일. 화면은 이 목록을 보고 실사/테스트 격자를 고른다(태블릿 4K, XR 8K 우선, 없으면 다른 크기)
- `strokes`는 `patch`로 바꿀 수 없다. `stroke:*` 메시지만 쓴다
- 상태는 서버 메모리에만 있다. 서버를 다시 켜면 초기화된다

| 방향 | type | 내용 |
|---|---|---|
| 화면 → 서버 | `patch` | `{ patch: { island: "2" } }` 부분 갱신. 허용되지 않은 키·값은 거부 |
| | `stroke:start` | `{ stroke: { id, tool, width, color, pts } }` |
| | `stroke:append` | `{ id, pts }` 50ms 배치, 1회 최대 200점 |
| | `stroke:end` · `stroke:erase` | `{ id }` |
| | `reset` | 초기 상태로 |
| | `ping` | 2초마다 연결 확인. 6초간 응답 없으면 다시 접속 |
| 서버 → 화면 | `hello` | 접속 직후. 클라이언트 번호, 아이패드 접속 주소 |
| | `snapshot` | 전체 상태. 접속·재접속·리셋 때 |
| | `patch` · `stroke:*` | 위 변경을 모든 화면에 중계 (`rev`, `from` 포함) |
| | `peers` | 접속 중인 태블릿·XR 수 |
| | `error` | 거부 사유 |
